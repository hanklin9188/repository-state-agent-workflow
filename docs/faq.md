# FAQ

## Is `ACTIVE.md` another project manager?

No. It is a tiny continuation pointer. Your task tracker remains the task tracker.

## Must every task use a new session?

No. The default is one substantial task per session. Small tightly related edits may stay together.

## What if a task requires broad architecture context?

Use progressive disclosure and a decision session. Broad context is allowed when required; it should not be the routine default.

## Does this work only with Codex?

No. The workflow is Markdown- and Git-based. Agent-specific instruction discovery varies, so adapt integration details while preserving the state architecture.

## Is conversation history useless?

No. It remains useful for interaction. It simply stops being the authoritative project database.

## Does a fresh session lose useful debugging knowledge?

Only if the debugging result was never written down. Record the durable conclusion, test, commit, or handoff—not the full stream of thought.

## Will this always save 80–90% of tokens?

No. Savings vary. Large long-lived sessions with repeated history benefit most; short focused tasks may see modest savings.
